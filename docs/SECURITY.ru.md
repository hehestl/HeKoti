# Политика безопасности HeKoti

## Сообщение об уязвимостях

Если вы обнаружили уязвимость безопасности, пожалуйста, сообщите об этом ответственно:

1. **Не создавайте публичный issue** - это может поставить под угрозу других пользователей
2. Отправьте отчет на email (если указан) или создайте приватный security advisory на GitHub
3. Предоставьте достаточно информации для воспроизведения проблемы
4. Дайте разумное время на исправление перед публичным раскрытием

## Реализованные меры безопасности

### Аутентификация и сессии
- **Хеширование паролей**: bcrypt с cost factor 12
- **Двухфакторная аутентификация (2FA)**: TOTP с шифрованием AES-256-GCM
- **Безопасные сессии**: 
  - Токены хешируются перед сохранением в БД
  - HttpOnly и Secure флаги на cookie
  - SameSite=Lax для защиты от CSRF
  - Настраиваемый TTL сессий

### Защита от атак
- **CSRF защита**: Double-submit cookie pattern для всех state-changing запросов
- **Rate limiting**: 
  - 20 попыток входа по IP за 5 минут
  - 10 попыток входа по email за 5 минут
  - 25 TOTP попыток по IP за 5 минут
- **Валидация email**: Строгая валидация формата email адресов

### Безопасность контента
- **Content Security Policy (CSP)**:
  - Один nonce на запрос в middleware; CSP только в HTTP-заголовке (не в `<meta>`)
  - Next.js автоматически ставит nonce на свои inline-скрипты (`strict-dynamic`)
  - В development допускается `'unsafe-eval'` для React DevTools
  - Ограничение источников скриптов (аналитика — отдельные домены)
- **Валидация HTML**: Санитизация пользовательского HTML в настройках
- **XSS защита**: Экранирование вывода, валидация входных данных

### Безопасность загрузки файлов
- **Валидация типов**: Проверка MIME типов и расширений
- **Ограничение размера**: Максимум 10MB для изображений
- **Безопасные имена**: Генерация безопасных имен файлов
- **Защита от path traversal**: Валидация путей к файлам

### Безопасность API
- **Валидация запросов**: Zod схемы для всех входящих данных
- **Ограничение размера payload**: Защита от DoS атак
- **Подпись webhook'ов**: HMAC-SHA256 для входящих webhook'ов
- **Безопасные заголовки**: 
  - X-Content-Type-Options: nosniff
  - X-Frame-Options: DENY
  - Strict-Transport-Security (в production)
  - Referrer-Policy: strict-origin-when-cross-origin

### Защита данных
- **Шифрование TOTP секретов**: AES-256-GCM с уникальным IV
- **Безопасное хранение**: Хеширование чувствительных данных
- **Минимизация информации об ошибках**: В production не раскрываются детали ошибок

## Рекомендации по развертыванию

### Обязательные настройки для production
1. Установите `HEKOTI_ENFORCE_PROD_SECRETS=1` для принудительной проверки секретов
2. Настройте сильные секреты (минимум 32 символа):
   - `WEBHOOK_SECRET`
   - `AUTH_PENDING_SECRET`
   - `HEKOTI_TOTP_ENCRYPTION_KEY`
3. Используйте HTTPS для всех соединений
4. Настройте `SESSION_COOKIE_INSECURE=0` (по умолчанию)
5. Установите разумный `SESSION_TTL_HOURS` (по умолчанию 720 часов = 30 дней)

### Дополнительные меры
1. Настройте reverse proxy (Nginx, Traefik, Caddy) для:
   - Терминации HTTPS
   - Дополнительного rate limiting
   - Блокировки подозрительных запросов
2. Регулярно обновляйте зависимости
3. Мониторьте логи на предмет подозрительной активности
4. Делайте резервные копии базы данных
5. Ограничьте доступ к админ-панели по IP (если возможно)

## Известные ограничения

1. **CSP 'unsafe-inline' для стилей**: Требуется для совместимости с CSS фреймворками
2. **Email валидация**: Использует regex, который может отклонять некоторые валидные но редкие email форматы
3. **Rate limiting**: Хранится в памяти при отсутствии Redis, что может быть недостаточно для распределенных систем
